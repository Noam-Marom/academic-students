סיימתי לבדוק את הטקסט, והבדיקה האוטומטית של כיוון הכתיבה עברה בלי שגיאות. אלה התוצאות:

## ההבדל בין fork ל-exec

הקריאה `fork` יוצרת תהליך חדש, ואילו הקריאה `exec` מחליפה את התוכנית שרצה בתהליך הקיים. בפועל משלבים בין השתיים: קודם `fork`, ואז ה-child מריץ אחריה את הקריאה `exec` על הקוד החדש.

## טבלת השוואה

| ההיבט | הקריאה fork | הקריאה exec |
|---|---|---|
| מטרה | יצירת תהליך חדש | הרצת תוכנית אחרת |
| מספר תהליכים | גדל באחד | נשאר אותו דבר |
| ה-PID | ל-child יש PID חדש | נשמר ללא שינוי |
| קוד וזיכרון | העתק של ה-parent | מוחלפים לגמרי בתוכנה החדשה |
| ערך מוחזר | אפס ב-child, ו-PID של ה-child ב-parent | לא חוזר בהצלחה, ורק בשגיאה מחזיר 1- |
| קובצי fd פתוחים | עוברים בירושה | נשארים פתוחים, אלא אם הוגדר `FD_CLOEXEC` |

## דוגמת קוד ב-C

הקוד הבא יוצר child שמריץ את הפקודה `ls`, וה-parent ממתין לו:

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();

    if (pid < 0) {
        perror("fork");
        exit(1);
    } else if (pid == 0) {
        execlp("ls", "ls", "-l", (char *)NULL);
        perror("execlp");   /* מגיעים לכאן רק אם exec נכשל */
        _exit(1);
    } else {
        wait(NULL);
        printf("child finished\n");
    }
    return 0;
}
```

הסבר קצר: ב-child הקריאה `execlp` מחליפה את הקוד בתוכנית `ls`, ולכן השורה שאחריה לא מתבצעת בהצלחה. ה-parent ממשיך בענף האחרון וממתין עם `wait` עד שה-child מסיים.
