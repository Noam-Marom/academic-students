## ההבדל בקצרה

- **`fork()`** יוצר **תהליך חדש** שהוא העתק כמעט מדויק של התהליך הקורא (אותו קוד, זיכרון, קבצים פתוחים). ההבדל היחיד הוא ערך ההחזרה: האב מקבל את ה-PID של הבן, והבן מקבל 0.
- **`exec()`** (משפחת `execl`, `execvp` ועוד) **מחליף את התוכנית** שרצה בתהליך הנוכחי בתוכנית חדשה. ה-PID נשאר זהה, ובדרך כלל הפונקציה לא חוזרת.

בפועל משלבים אותם: `fork` ליצירת תהליך, ואז `exec` בבן להרצת תוכנית אחרת. כך עובד ה-shell.

## טבלת השוואה

| מאפיין | `fork()` | `exec()` |
|---|---|---|
| מה הוא עושה | יוצר תהליך חדש | מחליף את תמונת התהליך הקיים |
| PID | חדש לבן | נשאר אותו PID |
| קוד וזיכרון | העתק (Copy-on-Write) | מוחלפים בתוכנית החדשה |
| ערך החזרה | PID באב, 0 בבן, -1 בכישלון | לא חוזר בהצלחה, -1 בכישלון |
| קבצים פתוחים | עוברים בירושה | נשארים פתוחים (אלא אם `FD_CLOEXEC`) |
| מספר תהליכים | גדל ב-1 | לא משתנה |

## דוגמת קוד

```c
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void) {
    pid_t pid = fork();

    if (pid < 0) {
        perror("fork");
        exit(1);
    }

    if (pid == 0) {
        // תהליך הבן: מחליפים אותו בתוכנית ls
        printf("Child (PID %d) running ls...\n", getpid());
        execlp("ls", "ls", "-l", NULL);
        // מגיעים לכאן רק אם exec נכשל
        perror("execlp");
        exit(1);
    } else {
        // תהליך האב: מחכה לבן
        int status;
        waitpid(pid, &status, 0);
        printf("Parent: child %d finished with status %d\n",
               pid, WEXITSTATUS(status));
    }
    return 0;
}
```

**מה קורה בקוד:** `fork` יוצר בן, הבן קורא ל-`execlp` ומוחלף בתוכנית `ls` (באותו PID), והאב ממתין לו עם `waitpid`.
